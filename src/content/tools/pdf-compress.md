# Compress PDF — Reduce PDF File Size Online Free

> Shrink your PDF files by up to 80% using canvas-based image re-encoding — entirely in your browser. No server uploads, no privacy risk, no file size limit.

## Why Compress PDFs?

Large PDF files create friction: slow email transfers, storage quota limits, upload rejections from web portals, and slow loading in web viewers. Our Compress PDF tool reduces file size by re-rendering each page at a configurable quality level using HTML5 Canvas and the pdf-lib library — all within your browser.

## How to Compress a PDF — Step by Step

1. **Upload your PDF** using the drag-and-drop zone or the file picker.
2. **Set the quality slider** between 10% (maximum compression, lower quality) and 100% (lossless, no compression).
3. **Click "Compress PDF"** — the tool renders each page and re-encodes it.

5. **Download** the compressed PDF.

Recommended quality settings:
- **70–80%**: Best balance for general documents and presentations.
- **40–60%**: Good for archiving scanned documents where perfect sharpness isn't critical.
- **10–30%**: Aggressive compression for draft sharing or low-bandwidth environments.

## Technical Process: Canvas-Based PDF Compression

The compression algorithm works by converting vector PDF content into rasterized JPEG images:

1. **Rendering**: Each page is rendered to an HTML5 `<canvas>` using pdfjs-dist at a scale derived from the quality setting.
2. **Re-encoding**: The canvas pixels are exported as JPEG data using `canvas.toDataURL('image/jpeg', quality)` where quality ranges from 0 to 1.
3. **Embedding**: Each JPEG is embedded into a new PDF page using pdf-lib's `embedJpg()` method.
4. **Output**: The resulting PDF is a raster-image-based document with significantly smaller file size.

**Note**: This method is ideal for documents that were originally scanned or image-heavy. For text-heavy PDFs, compression savings may be more modest.

## Frequently Asked Questions

### Will text remain selectable after compression?
In the current implementation, the output is a raster-image PDF. Text will appear correctly but will not be selectable or searchable. Use OCR afterward if text extraction is needed.
### Does compression affect image quality visibly?
At 70%+ quality, differences are virtually imperceptible on screen. Below 50%, compression artifacts may become noticeable on fine text and detailed images.
### Can I compress a password-protected PDF?
No. The PDF must be unlocked first. Use the PDF Protect & Unlock tool on this site.
### What is the maximum supported file size?
Browser RAM is the only constraint. A 200 MB PDF with many pages may take 2–3 minutes to process.
### Does this tool work on scanned PDFs?
Yes. Scanned PDFs (image-only) benefit most from this compression method.

## Worked Example: Shrinking a 42 MB Scanned Report to Under 10 MB

Karim has a 60-page scanned site report, `Site-Report.pdf`, that is 42 MB — too large for his company's email limit of 25 MB and far too large for the client portal's 10 MB cap. The report is image-only: every page is a scan, so text search does not matter to him.

**Step 1 — Try 70% quality first.** Karim uploads the file and sets the quality slider to 70%. The tool renders all 60 pages and produces an 18 MB file. The savings ratio is $savings = (42 - 18) / 42 \approx 0.57$, a 57% reduction. The text and site photographs still look sharp on screen, but 18 MB still exceeds the portal's 10 MB limit.

**Step 2 — Drop to 50% quality.** He runs the original 42 MB file again at 50% quality. The result is 9.4 MB, a saving of $savings = (42 - 9.4) / 42 \approx 0.78$, or about 78%. He zooms into a detailed engineering drawing on page 34 and finds the fine lines slightly softer but still legible, and the small print on page 41 remains readable.

**Step 3 — Keep the original.** He downloads the 9.4 MB version as `Site-Report-Compressed.pdf` for the portal, and keeps the original 42 MB file archived. He does not compress the 9.4 MB file a second time, because a second pass would soften the drawings further for very little extra saving.

## Common Mistakes

### Mistake 1: Compressing a text-heavy PDF and expecting an 80% saving
**Cause:** The compression method re-encodes pages as JPEG images, so a born-digital text PDF with almost no images has little to shrink — it may drop only 10–30% at 80% quality. **Fix:** Check the document type first. Scanned and image-heavy PDFs benefit most; for text PDFs, a small saving is normal, not a failure of the tool.

### Mistake 2: Compressing an already compressed file a second time
**Cause:** A 9 MB file is fed back in at 50% quality hoping for 4 MB, but JPEG re-encoding of JPEG pixels adds blur faster than it removes bytes. **Fix:** Always compress from the original file, and run the compression once at the quality level you actually need.

### Mistake 3: Choosing 10–30% quality for a document that will be printed
**Cause:** Aggressive compression looks acceptable as a thumbnail on a phone, but printed at full size the text breaks up and fine lines disappear. **Fix:** Use 70–80% for anything that will be printed or read closely, and reserve 10–30% for quick draft sharing where legibility of small print does not matter.

### Mistake 4: Forgetting that the output text is no longer selectable
**Cause:** The output is a raster-image PDF, so after compression you cannot select, copy, or search the text — a surprise when someone later needs to quote a paragraph. **Fix:** If searchable text matters, keep the original alongside the compressed copy, or run the compressed file through the PDF OCR tool afterwards.

## Frequently Asked Questions (Continued)

### How do I choose between 70% and 50% quality?
Use 70–80% when the PDF will be printed, archived, or read in detail. Use 50% when the file must fit a strict upload limit and slight softening is acceptable. In the example above, 70% gave 18 MB and 50% gave 9.4 MB from the same 42 MB source — test both on your own file, because the result depends on the content.

### Why did my 3 MB text PDF only shrink to 2.6 MB?
A born-digital text PDF is already stored efficiently as vector text, not as images. The tool's JPEG re-encoding has little redundant image data to remove, so a 10–30% saving at 80% quality is the expected result for that document type, as shown in the compression ratio table.

### Can I compress a PDF that is mostly photographs?
Yes, and photographs compress well. A photo-heavy presentation often shrinks by 30–50% at 80% quality and 55–70% at 50% quality. Check faces and detailed textures at full zoom after compressing, because JPEG artefacts show first in smooth gradients such as skies.

### Does compression remove embedded fonts or metadata?
The output is rebuilt from rendered page images, so the original embedded fonts and text layer are not carried over. The page dimensions are preserved, but treat the compressed file as a visual copy for sharing, and keep the original as the master.
